Arquitetura e módulos

Aplicação de página única, sem framework: um index.html com todas as telas, scripts globais carregados em ordem e um objeto DB em memória como fonte de dados.

Visão em camadas

Telas index.html + diario.css→Módulos de tela home, alunos, lançamento…→Estado DB + variáveis globais→Acesso a dados db.js / config.js→Microsoft Graph → Excel no OneDrive

Ordem de carga (index.html)

ui → config → db → listas → home → alunos → aluno-editar
   → lancamento → calendario → relatorio → financeiro → app

Não há módulos ES: tudo é global. As dependências cruzadas só são resolvidas em tempo de execução (por exemplo, config.js usa appConectado, declarada em app.js, que carrega por último). O init em app.js precisa que todos os anteriores estejam carregados.

Fluxo de leitura

usedRange: Diário→usedRange: Alunos→usedRange: Financeiro→usedRange: Listas→renderHome + Alunos + Calendário + Lançar

Cada aba é lida inteira (usedRange) e transformada em objetos. Linhas de título/cabeçalho são puladas por posição fixa (slice(2)).

Todas usam fetch direto, repetido em cada módulo, sem tratamento central de erro/token (P05, P08).

Decisões de projeto registradas

  • JS puro multi-arquivo, sem bundler (melhorias.md).
  • Somente as listas são cacheadas em localStorage; alunos, aulas e financeiro sempre vêm da planilha para evitar dados desatualizados.
  • Edição de aluno e pagamentos gravam imediatamente via Graph.
  • Financeiro usa a aba já existente no modelo.
